# SideQuest UI 改善盤點

## 基線

- 基線分支：`main`
- 基線 commit：`e0db3b2 fix(frontend): proxy production API to main backend`
- 改善分支：`ui/visual-polish`
- 檢視尺寸：桌面預設視窗、390 × 844 行動版
- 檢視範圍：探索首頁、活動清單、活動詳情、地圖浮動控制、Persona 對話框

## 第一階段問題清單

### 1. 文案與資訊層級

- 移除使用者不需要知道的內部標記：`BACKEND API`、`PRD 3-TIER RECOMMENDATIONS`、`ACTIVITY DETAIL`、`Demo 時段` 等。
- 將「你的城市 Agent · 使用者名稱」改為清楚的頁面上下文，避免品牌、角色、資料來源同時爭奪注意力。
- 將「正在即時推理台北活動、微氣候與捷運連通…」等工程狀態改為一般使用者能理解的進度文案。
- 收斂地圖圖例、模擬資料、資料來源提示；保留必要的資料透明度，但改成次要的說明層級。
- 統一動詞：探索、查看地圖、規劃路線、收藏、開啟活動頁，避免「查看／清除／重置」和符號混搭造成語意不一致。

### 2. 按鈕與互動元件幾何

- 建立一致的 icon button 尺寸、圓角、邊框、focus ring 與 hover/pressed 狀態，套用地圖控制、返回、關閉、重新整理、收藏與回饋按鈕。
- 修正詳情頁 quick actions 的圖示、文字與點擊區域對不齊問題，讓四個動作擁有一致的欄寬與最小觸控尺寸。
- 修正行動版底部導覽的 icon/label 垂直對齊與 active 狀態，避免 emoji 和文字造成基線歪斜。
- 修正 route preference、時段切換、filter chip 的高度與 active 狀態，使它們看起來是同一套選擇元件。
- 為只有符號的控制補齊可見 tooltip/title 與一致的 aria-label，不讓符號本身承擔全部語意。

### 3. 空間與可見度

- 降低 bottom sheet 預設高度與內距，讓地圖保留足夠可用視野；行動版避免 bottom sheet 與 bottom nav 疊壓內容。
- 將地圖錯誤/載入狀態收斂成不遮蔽主要操作的狀態提示，避免在地圖中央與圖例同時出現過多訊息。
- 重新安排行動版地圖控制和 sheet 的安全距離，控制按鈕不得被抽屜、圖例或底部導覽遮住。
- 降低過大的空白與過密的卡片內距，讓清單卡片優先呈現「名稱、日期/費用、地點、核心指標」。
- 將非必要的長說明、工程細節與次要提示改為可收合、次要文字或 tooltip。

### 4. 響應式與可操作性

- 以 390px 行動版和桌面版各做一次完整視覺回歸，特別檢查抽屜展開、最小化、詳情頁與底部導覽。
- 保留至少 44px 的主要觸控目標；不可因縮小文字而讓控制變得難按。
- 讓卡片、標籤、標題在窄螢幕自然換行，避免溢出、裁切或壓縮按鈕。
- 補足按鈕 focus-visible、disabled 和錯誤狀態的可見差異。

## 驗收條件

- 首頁不再顯示 PRD、Backend API 等開發內部字樣。
- 桌面與 390px 行動版的地圖控制、bottom sheet、bottom nav 不互相遮擋。
- 主要按鈕與 icon button 具一致尺寸和對齊，收藏、詳情返回/關閉、filter、時段切換可辨識且可操作。
- `npm test`、`npm run build`、`git diff --check` 通過。
- 修正完成後再檢查 `main` 新增功能差異，若有同類 UI 問題，併入 merge 前檢查清單，不直接混入未驗證的功能變更。
